# PostgreSQL 17 编译产物跨机器迁移操作手册

> 适用场景：在一台 CentOS 7 机器上用 `install_postgresql.sh` 源码编译安装了 PostgreSQL 17.11（含 PostGIS 3.5.7、pgvector、TimescaleDB 扩展，GEOS/PROJ/SQLite 编译在 `/usr/local`），现需要把**编译好的程序**整体迁移到另一台机器，**在新机器上重新初始化 data 数据目录**，并保证所有插件/扩展正常使用。
>
> 本文以实际安装路径为例（**源机/目标机路径见下，本文目标机统一用 `/mnt/data`**）：
> - 源机 PG 安装目录：`/home/data/postgresql/postgresql-17.11`（仅打包时引用，保持源机实际路径）
> - 目标机 PG 安装目录（`$PG_HOME`）：`/mnt/data/postgresql/postgresql-17.11`
> - 目标机数据目录（全新初始化，`$PGDATA`）：`/mnt/data/postgresql/data`
> - 目标机系统库目录（`$SYSLIB`）：`/mnt/data/postgresql/pg17-syslib`（与 PG 安装目录同级，统一在 `/mnt/data/postgresql/` 下管理）
> - 各压缩包统一放在目标机 `/mnt/data/` 下
> - 运行用户/组：`postgres` / `postgres`；systemd 服务名：`postgresql17.service`
> - 自研依赖库：GEOS 3.9.3 / PROJ 6.3.2 / SQLite 3.46.0，**固定在 `/usr/local`**
>
> 命令里凡出现 `/mnt/data/postgresql/...` 均指目标机路径，如你的目标机路径不同请整体替换。
>
> **变量名约定（与安装脚本一致）**：PG 安装目录环境变量为 **`PG_HOME`**、数据目录为 **`PGDATA`**（由 `install_postgresql.sh` / 迁移部署脚本写入 `/etc/profile`），全文手工命令同样使用 `PG_HOME`，不存在 `PGHOME` 这一变量名。

## 一、迁移原理与前提条件（务必先读）

### 1. 哪些东西可以直接拷贝

| 内容 | 位置 | 能否直接迁移 |
|---|---|---|
| PostgreSQL 程序本体（bin/lib/share/include） | 源机 `/home/data/postgresql/postgresql-17.11` → 目标机 `/mnt/data/postgresql/postgresql-17.11` | ✅ 整目录打包（目标机可放任意位置） |
| PostGIS / pgvector / TimescaleDB 扩展文件 | `$PG_HOME/share/extension/`、`$PG_HOME/lib/`（已随 PG 目录一起） | ✅ 随 PG 目录 |
| GEOS / PROJ / SQLite 自研库 | `/usr/local/lib`、`/usr/local/bin`、`/usr/local/include`、`/usr/local/share/proj`（源机/目标机同路径，固定不可改） | ✅ 打包 |
| 动态库搜索路径配置 | 目标机 `/etc/ld.so.conf.d/pg17-syslib.conf`（命名与 `pg17-syslib.tar.gz` 一致） | ⚠️ **无需拷贝源机配置**，目标机按第四节第 3 步统一生成（三行路径） |
| 操作系统运行时库（libstdc++、libxml2、json-c、readline、zlib、openssl、ICU 等；glibc 核心库除外） | `/usr/lib64` | ⚠️ 不随 PG 包走；离线用方案 A 从源机收集（glibc 核心库目标机自带，不拷） |
| data 数据目录 | `$PG_HOME/../data` | ❌ **不迁移**，目标机全新 initdb（本手册目标） |
| systemd 服务文件 | `/etc/systemd/system/postgresql17.service` | ⚠️ 目标机重新生成（含绝对路径，重建更稳妥） |

### 2. 必须满足的兼容性前提

二进制文件是编译产物，**不能跨不兼容的环境拷贝**，目标机必须满足：

1. **CPU 架构相同**：源机和目标机都是 `x86_64`（用 `uname -m` 确认，都应输出 `x86_64`）。
2. **操作系统大版本一致**：都是 CentOS / RHEL 7（glibc 主版本一致）。
   - CentOS 7 的 glibc 是 2.17。若目标机是 CentOS 8/9、Ubuntu、Debian、麒麟/统信等其他系统，**不要直接迁移**，请见 [第八节：不能直接迁移时的处理](#八不能直接迁移时的处理)。
3. **自研库路径固定，PG 目录可整体移动**：
   - GEOS/PROJ/SQLite 是按绝对路径链接的，**必须固定在 `/usr/local`**（deps 包已打成该路径，直接 `-C /` 解压即可）。
   - PG 程序目录（含 bin/lib/share/扩展）可整体移动到任意位置——PG 运行时按二进制相对路径找 `../lib`、`../share`，所以目标机放到 `/mnt/data/postgresql/postgresql-17.11` 可正常运行。但**必须保证库目录（`$PG_HOME/lib`、`/usr/local/lib`、`$SYSLIB`）已注册给 ldconfig**（见第四节第 3 步）。
   - 唯一写死源机路径的是 `pg_config`（仅在目标机**重新编译扩展**时才用到）。本方案直接迁移已编译好的扩展，不重编译，故不受影响。若将来要在目标机重编译扩展，请见第八节。

> 快速自检（两台机器都执行并对比）：
> ```bash
> uname -m                      # 应为 x86_64
> cat /etc/redhat-release       # 应为 CentOS Linux release 7.x
> ldd --version | head -1       # glibc 版本应一致（CentOS 7 为 2.17）
> ```

## 零、自动化脚本（推荐）

本手册的全部步骤已做成两个交互式脚本，与本文同目录：

| 脚本 | 执行机器 | 作用 |
|---|---|---|
| `migrate_pg17_pack.sh` | **源机** | 一键打出 pg17-bin / pg17-deps / pg17-syslib / pg17-conf（含 postgresql.conf、pg_hba.conf、postgresql17.service）四个包 + pg17-migrate.env 路径清单 + pg17-ldd.txt |
| `migrate_pg17_deploy.sh` | **目标机** | 一键完成：建 postgres 用户 → 解压三包 → 写 pg17-syslib.conf + ldconfig → ldd 校验 → initdb → 覆盖源机配置（自动替换旧路径）→ 装 systemd 服务并启动 → 写 `/etc/profile` 环境变量（`PG_HOME`/`PGDATA`，与安装脚本一致）→ CREATE EXTENSION 并验证 |

用法：

```bash
# 源机
bash migrate_pg17_pack.sh
# 把 /mnt/data/pg17-* 和 pg17-migrate.env 拷到目标机 /mnt/data，再上传 deploy 脚本后：
# 目标机
bash migrate_pg17_deploy.sh
```

两个脚本均为交互式（每个路径都有默认值，回车即用），并已处理以下细节：

- **路径自动探测**：pack 脚本优先读源机环境变量 `PG_HOME`/`PGDATA`，其次探测正在运行的 postgres 进程，最后扫描常见安装目录；
- **路径替换**：deploy 读取 `pg17-migrate.env`（字段为 `SOURCE_PG_HOME`/`SOURCE_PGDATA`）里的源机路径，自动把配置/service 文件中的旧路径 sed 替换为目标机路径；
- **端口自适应**：从目标机 `postgresql.conf` 解析实际 `port`，`pg_isready`/`psql` 均带 `-p`（源机改过端口也能正常验证）；
- **PG 目录名自适应**：解压时若包内顶层目录名与目标 PG_HOME 目录名不同，自动重命名；
- **环境变量统一**：deploy 结束前会把 `PG_HOME`/`PGDATA`/`PATH`/`MANPATH` 写入 `/etc/profile`（幂等，重复执行会先剔除旧块再追加），与 `install_postgresql.sh` 的安装结果完全一致，重新登录或 `source /etc/profile` 后直接可用 `psql`；
- **失败保护**：ldd 校验发现缺库、服务启动失败时会打印日志并中止（initdb 已做则跳过，可修好后重跑）；已初始化过的 data 目录不会重复 initdb；
- **打包自检**：pack 脚本会校验 bin 包含 postgis 扩展、deps 包含 proj.db，缺失时给出警告；打包时源机缺少个别依赖文件只会警告跳过，不会中断。

脚本中每一步都对应下文的手工命令；若需理解原理或排查问题，继续阅读下文各节。

## 二、第一步：在源机器上打包

以下命令在**已装好 PG 的源机器**上以 root 执行。

### 1. 打包 PostgreSQL 安装目录（含全部扩展文件，不含 data）

```bash
cd /home/data/postgresql
# 只打包程序目录 postgresql-17.11，不打包 data（数据目录到新机重新初始化）
tar -zcf /mnt/data/pg17-bin.tar.gz -C /home/data/postgresql postgresql-17.11
ls -lh /mnt/data/pg17-bin.tar.gz
```

确认包内扩展文件存在（应能看到 postgis、vector、timescaledb）：

```bash
tar -tzf /mnt/data/pg17-bin.tar.gz | grep -E 'postgis.*\.(control|so)|vector\.(control|so)|timescaledb.*\.(control|so)' | head -30
```

### 2. 打包 /usr/local 下的自研依赖库（GEOS / PROJ / SQLite）

这些库是脚本源码编译安装的，目标机 yum 里没有对应版本，必须一起迁移。

```bash
tar -zcf /mnt/data/pg17-deps.tar.gz -C / \
  usr/local/lib/libgeos* \
  usr/local/lib/libproj* \
  usr/local/lib/libsqlite3* \
  usr/local/lib/pkgconfig/geos*.pc \
  usr/local/lib/pkgconfig/proj.pc \
  usr/local/lib/pkgconfig/sqlite3.pc \
  usr/local/bin/geos-config \
  usr/local/bin/proj \
  usr/local/bin/projinfo \
  usr/local/bin/cs2cs \
  usr/local/bin/cct \
  usr/local/bin/gie \
  usr/local/bin/sqlite3 \
  usr/local/include/geos* \
  usr/local/include/proj* \
  usr/local/include/proj.h \
  usr/local/include/sqlite3.h \
  usr/local/share/proj \
  usr/local/lib/cmake/geos* \
  usr/local/lib/cmake/proj* \
  2>/dev/null
ls -lh /mnt/data/pg17-deps.tar.gz
```

> 说明：`usr/local/share/proj` 里是 PROJ 的坐标参考数据（`proj.db` 等），**PostGIS 运行时必须**，缺失会导致空间投影函数报错，务必打包。

### 3.（可选）查看源机 ldconfig 配置，仅供参考

源机的 `/etc/ld.so.conf.d/local-pg-ext.conf`（内容仅一行 `/usr/local/lib`）**不需要拷贝到目标机**：
目标机在第四节第 3 步会统一生成 `/etc/ld.so.conf.d/pg17-syslib.conf`（包含 `$PG_HOME/lib`、`/usr/local/lib`、`$SYSLIB` 三行），已完全覆盖它。可在源机看一眼确认源库路径：

```bash
cat /etc/ld.so.conf.d/local-pg-ext.conf    # 源机内容通常为一行：/usr/local/lib
```

### 4. 生成运行时动态库依赖清单（用于目标机核对）

在源机上执行，把所有二进制依赖的系统库列出来，作为目标机缺库时的对照依据：

```bash
{
  echo "===== postgres 主程序 ====="
  ldd /home/data/postgresql/postgresql-17.11/bin/postgres
  echo "===== PostGIS 扩展 ====="
  ldd /home/data/postgresql/postgresql-17.11/lib/postgis-3.so
  echo "===== pgvector 扩展 ====="
  ldd /home/data/postgresql/postgresql-17.11/lib/vector.so
  echo "===== TimescaleDB 扩展 ====="
  ldd /home/data/postgresql/postgresql-17.11/lib/timescaledb-*.so
} > /mnt/data/pg17-ldd.txt 2>&1
cat /mnt/data/pg17-ldd.txt
```

记下输出中所有 `=> /usr/lib64/...` 的系统库名（如 `libxml2.so.2`、`libjson-c.so.2`、`libstdc++.so.6`、`libreadline.so.6`、`libz.so.1`、`libssl/libcrypto` 等），目标机上必须都能找到。

### 5.（离线环境必做）收集系统运行时库

目标机若**无法联网 yum**，则把 PG 及各扩展依赖的 `/usr/lib64` 系统运行时库也从源机一并收集打包。
以下脚本在**源机**执行：自动用 ldd 解析所有二进制/扩展的依赖，只收集 `/usr/lib64` 下的库，
**跳过 glibc 核心库**（libc/ld-linux 等，目标机 CentOS 7 自带、跨机拷贝有风险），并保留符号链接：

```bash
PG_HOME=/home/data/postgresql/postgresql-17.11
list=/mnt/data/pg17-syslib.list
: > "$list"

for bin in "$PG_HOME/bin/postgres" "$PG_HOME/bin/psql" "$PG_HOME/lib/"*.so; do
  ldd "$bin" 2>/dev/null
done | \
  awk '{for(i=1;i<=NF;i++) if($i ~ /^\//) print $i}' | \
  sed 's#^/lib64/#/usr/lib64/#' | \
  grep '^/usr/lib64/' | sort -u | \
  while read -r lib; do
    # 跳过 glibc 核心库（目标机系统自带，不跨机拷贝）
    case "$(basename "$lib")" in
      ld-*|libc.*|libc-*|libm.*|libm-*|libdl.*|libdl-*|librt.*|librt-*|\
      libpthread.*|libpthread-*|libresolv.*|libresolv-*|libutil.*|libutil-*|\
      libcrypt.*|libcrypt-*|libnsl*|libnss_*|libcidn*|libBrokenLocale*|\
      libanl.*|libanl-*) continue;;
    esac
    echo "$lib"                      # soname 软链（如 libstdc++.so.6）
    [ -L "$lib" ] && readlink -f "$lib"   # 软链指向的真实文件（如 libstdc++.so.6.0.19）
  done | sort -u > "$list"

wc -l "$list"
# 打包（不要加 -h，需保留 libxxx.so.N -> libxxx.so.N.M 软链关系）
# 提示 "tar: Removing leading '/' from member names" 属正常：tar 把绝对路径存为
# 相对路径 usr/lib64/...，目标机用 --strip-components=2 解压到独立目录。
tar -zcf /mnt/data/pg17-syslib.tar.gz -T "$list"
ls -lh /mnt/data/pg17-syslib.tar.gz
# 可抽查包内容（应能看到 libjson-c、libxml2、libstdc++、libreadline 等）
tar -tzf /mnt/data/pg17-syslib.tar.gz | grep -E 'json-c|xml2|stdc|readline' | head
```

### 6. 把文件传到目标机

```bash
# 在源机执行（把 目标IP 换成实际 IP）
# 必传：3 个 tar.gz；pg17-ldd.txt 仅为目标机缺库时对照用（可选）
scp /mnt/data/pg17-bin.tar.gz /mnt/data/pg17-deps.tar.gz /mnt/data/pg17-syslib.tar.gz \
    /mnt/data/pg17-ldd.txt root@目标IP:/mnt/data/
```

> 离线环境用 U 盘/内网 scp 均可；目标机只需收到这几个 `.tar.gz` 文件即可，无需联网。
> **不需要传** ld.so.conf.d 的配置文件——目标机的 `/etc/ld.so.conf.d/pg17-syslib.conf` 在第四节第 3 步按目标机实际路径现场生成。

## 三、第二步：在目标机器上安装系统运行时依赖

以下命令在**目标机器**上以 root 执行。这一步解决"不能迁移、必须用 yum 安装"的部分。

PG 与扩展运行需要一批系统运行时库：`libxml2`、`json-c`、`libstdc++`、`libgcc`、
`readline`、`zlib`、`openssl-libs`、`libuuid`、`libicu`、`lz4`、`libzstd` 等。
这些属于操作系统库、**不能随 PG 目录拷贝**，必须在目标机就位。按目标机能否联网选择方案：

| 方案 | 适用环境 | 是否需要网络 |
|---|---|---|
| **方案 A（推荐）** 源机收集运行时库拷贝 | 纯离线、无 yum 源 | ❌ 全程离线 |
| 方案 B RPM 离线包 | 有另一台同版本可联网 CentOS 7 | 下载机需联网 |
| 方案 C CentOS 安装 ISO 做本地 yum 源 | 有 CentOS 7 ISO 镜像 | ❌ 离线 |
| 方案 D 直接 yum | 目标机能访问 yum 源 | ✅ 需联网 |

#### 方案 A：拷贝源机运行时库（纯离线，推荐）

第二步第 5 小节已在源机生成 `pg17-syslib.tar.gz`。目标机解压到**独立目录**（不覆盖系统库），
再加入 ldconfig 搜索路径。库与源机同为 CentOS 7 编译，glibc 一致可直接运行。

> **解压目录可任意指定**，不强制 `/opt`：只要路径持久稳定（别放 `/tmp`，重启会清空）、
> 对所有用户可读、且与下方 `ld.so.conf.d` 配置里写的路径一致即可。下例统一放在
> `/mnt/data/postgresql/pg17-syslib`（与 PG 安装目录同级，便于统一管理）；
> 想换路径只需改 `SYSLIB` 一个变量。

```bash
# 库解压目录（与 PG 安装目录同级，可自定义为 /opt/pg17-syslib 等持久路径）
SYSLIB=/mnt/data/postgresql/pg17-syslib

# 解压到独立目录（--strip-components=2 去掉包内的 usr/lib64 前缀）
mkdir -p "$SYSLIB"
tar -zxf /mnt/data/pg17-syslib.tar.gz --strip-components=2 -C "$SYSLIB"
ls "$SYSLIB" | head      # 应直接看到 libjson-c.so.2 等文件，而非嵌套 usr/lib64

# 加入动态库搜索路径（此处先写系统库目录；第四节第 3 步会把它连同 PG lib、/usr/local/lib
# 一起统一写入 /etc/ld.so.conf.d/pg17-syslib.conf，全程只用这一个配置文件
# （文件名与 pg17-syslib.tar.gz 对应）
echo "$SYSLIB" > /etc/ld.so.conf.d/pg17-syslib.conf
ldconfig
```

> **顺序不能反：必须「先解压 tar（库文件到位）→ 再写 conf → 最后 ldconfig」。**
> ldconfig 只扫描**当时已存在**的目录并重建缓存；若先 ldconfig 后解压，新库不会进缓存，
> 必须补跑一次 `ldconfig`。后续凡往这三个目录新增过库文件（如补拷 ICU），同样要重跑 `ldconfig`。

> 若第四步 `ldd` 校验时仍有个别库 `not found`（收集脚本未覆盖到的工具库），
> 在**源机**上按缺库名补拷贝后，追加到 `$SYSLIB` 再 `ldconfig`：
> ```bash
> SYSLIB=/mnt/data/postgresql/pg17-syslib
> # 源机执行（把 缺失库名 换成实际 soname，如 libxxx.so.1）
> cp -av "$(ldconfig -p | grep '缺失库名' | awk '{print $NF}' | head -1)" /mnt/data/
> scp /mnt/data/缺失库名 root@目标IP:"$SYSLIB"/
> # 目标机执行
> ldconfig
> ```

#### 方案 B：RPM 离线包（有一台同版本可联网机器时）

在一台**与目标机同为 CentOS 7 x86_64 且能联网**的机器上下载 RPM 及依赖，拷贝到目标机安装：

```bash
# === 联网的下载机上执行 ===
yum install -y yum-utils epel-release
mkdir -p /mnt/data/pg17-rpms && cd /mnt/data/pg17-rpms
yumdownloader --resolve --destdir /mnt/data/pg17-rpms \
  libxml2 json-c libstdc++ libgcc readline zlib openssl-libs \
  libuuid libicu lz4 libzstd tar gzip
# 打包
tar -zcf /mnt/data/pg17-rpms.tar.gz -C /mnt/data pg17-rpms

# === 目标机上执行（离线）===
tar -zxf /mnt/data/pg17-rpms.tar.gz -C /mnt/data
rpm -Uvh --replacepkgs /mnt/data/pg17-rpms/*.rpm
```

> 若 `yumdownloader` 因包已安装而未下载，改用 `reinstall`：
> `yum reinstall --downloadonly --downloaddir=/mnt/data/pg17-rpms libxml2 json-c ...`

#### 方案 C：CentOS ISO 做本地 yum 源（有 ISO 镜像时）

```bash
# 挂载 CentOS 7 Everything/DVD 镜像
mount -o loop /root/CentOS-7-x86_64-DVD.iso /mnt
cat > /etc/yum.repos.d/localiso.repo <<'EOF'
```

## 四、第三步：在目标机器上解压部署

目标机上以 root 执行。PG 程序目录可放在任意位置（本文用 `/mnt/data/postgresql`）；`/usr/local` 固定不可改。

### 1. 解压 PG 程序

```bash
# 包内顶层目录就是 postgresql-17.11/（打包时用 -C /home/data/postgresql），
# 所以解压到 /mnt/data/postgresql 后得到 /mnt/data/postgresql/postgresql-17.11
tar -zxf /mnt/data/pg17-bin.tar.gz -C /mnt/data/postgresql
chown -R postgres:postgres /mnt/data/postgresql/postgresql-17.11
```

### 2. 解压自研依赖库到 /usr/local

```bash
# 注意：这里必须是 -C / （根目录），不是 -C /usr/local
tar -zxf /mnt/data/pg17-deps.tar.gz -C /
```

> **为什么是 `-C /` 而不是 `-C /usr/local`？**
> 打包时（第二步）用的是 `tar -C / usr/local/lib/libgeos* usr/local/share/proj ...`，
> 包内文件自带 `usr/local/...` 这层相对路径。解压到根目录 `/` 后，会自动还原成
> `/usr/local/lib/...`、`/usr/local/share/proj/...`。
> - 若写成 `-C /usr/local`，文件会落到 `/usr/local/usr/local/lib/...`，路径嵌套错误，程序找不到库。
> - 三个包的解压方式不同，注意区分：
>   - **deps 包**：包内是 `usr/local/...`，用 `-C /` 还原到 `/usr/local`；
>   - **PG 程序包**：包内顶层是 `postgresql-17.11/`，用 `-C /mnt/data/postgresql`（想放哪就解到哪）；
>   - **系统库包**：包内是 `usr/lib64/...`，用 `--strip-components=2 -C "$SYSLIB"` 去掉前两级前缀、平铺到库目录。

解压后确认文件落到了正确位置：

```bash
ls /usr/local/lib/libgeos_c.so* /usr/local/lib/libproj.so* /usr/local/lib/libsqlite3.so*
ls /usr/local/share/proj/proj.db        # PROJ 投影数据，PostGIS 坐标转换必需
```
能列出文件即正确；若提示 `No such file`，说明解压目录不对，检查是否误用了 `-C /usr/local`。

### 3. 配置动态库搜索路径并刷新

需要把**三类库路径**都注册给 ldconfig，缺一不可：
1. PG 自己的 lib 目录（`$PG_HOME/lib`，内含 libpq/libecpg/libpgtypes 及各扩展 .so）；
2. `/usr/local/lib`（GEOS/PROJ/SQLite）；
3. 系统库目录 `$SYSLIB`（方案 A 解压的 ICU/ssl/xml2 等）。

```bash
export PG_HOME=/mnt/data/postgresql/postgresql-17.11   # 目标机实际 PG 目录
SYSLIB=/mnt/data/postgresql/pg17-syslib                # 方案 A 的系统库目录（与 PG 安装目录同级）

cat > /etc/ld.so.conf.d/pg17-syslib.conf <<EOF
$PG_HOME/lib
/usr/local/lib
$SYSLIB
EOF
cat /etc/ld.so.conf.d/pg17-syslib.conf     # 三行路径都应存在
ldconfig
```

> **全程只用 `/etc/ld.so.conf.d/pg17-syslib.conf` 这一个文件**（文件名与系统库包
> `pg17-syslib.tar.gz` 对应；第三节方案 A 先写了 `$SYSLIB` 一行，这里用完整三行覆盖它）。
> 若漏写 `$PG_HOME/lib` 会报 `libpq.so.5 => not found`；漏写 `$SYSLIB` 会报
> `libicui18n.so.50 => not found`——这些库文件本身就在，只是没被 ldconfig 收录。

### 4. 验证二进制能正常加载、无缺库

```bash
export PG_HOME=/mnt/data/postgresql/postgresql-17.11

# 版本能正常输出
$PG_HOME/bin/postgres --version
$PG_HOME/bin/psql --version

# 关键：检查 postgres 及所有扩展动态库是否有 "not found"
for f in "$PG_HOME/bin/postgres" "$PG_HOME/lib/"*.so; do
  ldd "$f" 2>/dev/null | grep -i 'not found' && echo "  ^-- 缺库位于: $f"
done
```

- **以上命令没有任何输出** = 所有依赖库都已就位。
- 如果出现 `xxx.so => not found`：
  - 若是 `libgeos/libproj/libsqlite3` 相关 → 检查 `/usr/local/lib` 是否解压成功、`ldconfig` 是否执行。
  - 若是系统库（如 `libjson-c.so.2`、`libxml2.so.2`）→ 离线环境按第三节**方案 A 的补库方法**从源机拷该库到库目录（`$SYSLIB`，默认 `/mnt/data/postgresql/pg17-syslib`）后 `ldconfig`；联网环境用 `yum provides '*/库文件名'` 安装。
  - 可对照源机带来的 `/mnt/data/pg17-ldd.txt` 逐项核对。

## 五、第四步：全新初始化 data 数据目录

目标机上以 root 执行（用 postgres 身份初始化）。

```bash
export PG_HOME=/mnt/data/postgresql/postgresql-17.11
export PGDATA=/mnt/data/postgresql/data

mkdir -p "$PGDATA"
chown -R postgres:postgres "$PGDATA"
chmod 700 "$PGDATA"

# 以 postgres 用户初始化（UTF8 编码、支持中文排序）
su - postgres -c "$PG_HOME/bin/initdb -D $PGDATA --encoding=UTF8 --locale=C -U postgres"
```

> 说明：
> - `-U postgres` 指定数据库超级用户名。
> - `--locale=C` 性能最好；如需中文排序可用 `--locale=zh_CN.UTF-8`（需目标机已装中文 locale，`localedef -c -f UTF-8 -i zh_CN zh_CN.UTF-8`）。
> - 这一步生成的是**全新空数据库**，不包含源机任何业务数据。如需迁移业务数据，应在源机用 `pg_dump`/`pg_dumpall` 逻辑导出后导入新机（物理 data 目录不在本手册范围内）。

## 六、第五步：配置并启动数据库

### 1. 修改 postgresql.conf

```bash
CONF=$PGDATA/postgresql.conf

# 监听所有网卡（按需）
echo "listen_addresses = '*'" >> $CONF
echo "port = 5432" >> $CONF

chown postgres:postgres $CONF
```

> PostGIS 和 pgvector **不需要**预加载，普通 `CREATE EXTENSION` 即可；只有 TimescaleDB 需要 `shared_preload_libraries`。

### 2. 配置客户端认证（可选，按需开放远程）

```bash
HBA=$PGDATA/pg_hba.conf
# 允许局域网密码连接（示例，按实际网段调整）
echo "host    all    all    0.0.0.0/0    md5" >> $HBA
chown postgres:postgres $HBA
```

### 3. 创建 systemd 服务

```bash
cat > /etc/systemd/system/postgresql17.service << EOF
[Unit]
Description=PostgreSQL 17 Server
After=network.target

[Service]
Type=forking
User=postgres
Group=postgres
PIDFile=$PGDATA/postmaster.pid
ExecStart=$PG_HOME/bin/pg_ctl start -D $PGDATA -l $PGDATA/postgresql.log
ExecStop=$PG_HOME/bin/pg_ctl stop -D $PGDATA
ExecReload=$PG_HOME/bin/pg_ctl reload -D $PGDATA
Restart=on-failure
RestartSec=5s
Environment=PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

[Install]
WantedBy=multi-user.target
EOF

chmod 700 /etc/systemd/system/postgresql17.service
systemctl daemon-reload
systemctl enable postgresql17
systemctl start postgresql17

# 查看状态
systemctl status postgresql17 --no-pager
```

若启动失败，查看日志：


## 八、不能直接迁移时的处理

以下情况**二进制拷贝不可行**（glibc/架构/路径不兼容），应在目标机器上用安装脚本**重新源码编译**，脚本会自动编译 GEOS/PROJ/SQLite 及各扩展。

### 1. 判断是否需要重编译

| 情况 | 处理方式 |
|---|---|
| 目标机同为 CentOS 7 x86_64 | 按第二～七节直接迁移 |
| 目标机是 CentOS 8/9、RHEL 8/9、Rocky/Alma、Ubuntu、Debian、麒麟、统信等 | **需重编译**（glibc 版本不同，二进制可能无法运行） |
| 目标机无法保持 `/usr/local` 路径（GEOS/PROJ/SQLite 按该绝对路径链接） | **需重编译**（自研库路径编译期写死） |
| 只是 PG 程序目录想换位置（如不放 `/home/data` 而放 `/mnt/data`） | **无需重编译**：PG 按二进制相对路径找 `../lib`、`../share`，整目录可任意移动，解压后把 `$PG_HOME/lib` 写入 pg17-syslib.conf 即可 |
| 架构不同（aarch64/ARM 等） | **需重编译** |
| `ldd` 出现 `not found` 且 yum 装不到对应版本库 | 优先重编译对应依赖 |

### 2. 在目标机重编译的命令

把整个脚本目录拷到目标机，直接运行安装脚本（它会自动检测、源码编译 GEOS 3.9.3 / PROJ 6.3.2 / SQLite 及 PostGIS/pgvector/TimescaleDB）：

```bash
# 1) 安装编译工具链与依赖（需 yum 源）
yum groupinstall -y "Development Tools"
yum install -y epel-release
yum install -y \
  readline-devel zlib-devel openssl-devel libxml2-devel json-c-devel \
  libuuid-devel libicu-devel lz4-devel libzstd-devel \
  wget tar gzip make cmake3 gcc-c++ perl

# 2) 上传脚本后执行（交互菜单里选择安装 PostgreSQL 17 + 扩展）
chmod +x install_postgresql.sh
./install_postgresql.sh
```

> **离线环境重编译**：上述 `*-devel` 包和编译工具链同样无法在线安装，需二选一准备：
> - 用 **CentOS 7 Everything ISO** 挂成本地源（见第三节方案 C），Everything 镜像包含 `Development Tools` 及大部分 `*-devel` 包；
> - 在一台同版本可联网的 CentOS 7 上用
>   `yumdownloader --resolve --destdir=/mnt/data/devrpms gcc gcc-c++ make cmake3 tar gzip wget perl readline-devel zlib-devel openssl-devel libxml2-devel json-c-devel libuuid-devel libicu-devel lz4-devel libzstd-devel`
>   下载后拷到目标机 `rpm -Uvh --replacepkgs /mnt/data/devrpms/*.rpm` 离线安装。
>
> 另外源码编译需要联网下载各源码包（PG、GEOS、PROJ、SQLite、PostGIS 等）。离线时请先在可联网机器
> 下载对应源码 tar 包，放到脚本期望的本地缓存目录（或修改脚本指定本地包路径），脚本检测到本地包会直接使用、不再联网。

> 脚本在老版 gcc（如 CentOS 7 的 gcc 4.8.5）上会自动对 SQLite 降优化、对 PROJ 降单线程编译，并在 protobuf-c 版本过低时自动 `--without-protobuf` 安装 PostGIS，无需人工干预。

### 3. 仅重编译某个依赖（个别缺库时）

若只是个别自研库在目标机异常，可单独源码编译。以 PROJ 为例（GEOS/SQLite 同理）：

```bash
# PROJ 6.3.2 示例（需先有 sqlite3）
yum install -y sqlite-devel
cd /mnt/data
tar -zxf proj-6.3.2.tar.gz && cd proj-6.3.2
./configure --prefix=/usr/local
make -j1            # 内存小用 -j1 避免并行编译 OOM
make install
ldconfig
```

## 十、常见问题

**Q1：启动报错 `error while loading shared libraries: libgeos_c.so.1: cannot open shared object file`**
→ `/usr/local/lib` 没在库搜索路径。确认 `/etc/ld.so.conf.d/pg17-syslib.conf` 存在且包含 `/usr/local/lib`（另两行应为 `$PG_HOME/lib` 和 `$SYSLIB`），然后执行 `ldconfig`。

**Q2：CREATE EXTENSION postgis 报 `could not load library ".../postgis-3.so": libproj.so.15: cannot open...`**
→ 依赖包没解压到 `/usr/local/lib`，或没 `ldconfig`。重新解压 `pg17-deps.tar.gz -C /`（注意是根目录 `-C /`），确认 `/etc/ld.so.conf.d/pg17-syslib.conf` 含 `/usr/local/lib` 后 `ldconfig`。

**Q3：PostGIS 查询投影时报 `proj_obj_create: cannot find proj.db`**
→ PROJ 数据文件缺失。确认 `/usr/local/share/proj/proj.db` 存在（来自依赖包的 `usr/local/share/proj`）。

**Q4：CREATE EXTENSION timescaledb 报 `must be preloaded via shared_preload_libraries`**
→ 在 `postgresql.conf` 配置 `shared_preload_libraries = 'timescaledb'` 后**重启**数据库（不是 reload），再创建扩展。

**Q5：目标机是 ARM / 麒麟 / 统信 / CentOS 8+，能直接拷吗？**
→ 不能。请按第八节在目标机用 `install_postgresql.sh` 重新源码编译。

**Q6：想把源机的业务数据也带过去怎么办？**
→ 本手册只迁移程序并全新初始化。业务数据请在源机 `pg_dumpall` 或 `pg_dump` 导出，新机初始化后用 `psql`/`pg_restore` 导入（逻辑备份，跨版本兼容性最好）。

**Q7：目标机离线，yum 报 `Connection timed out` / 无法访问镜像源怎么办？**
→ 不要依赖 yum。按第三节**方案 A**：在源机用第二步第 5 小节脚本收集系统运行时库打成 `pg17-syslib.tar.gz`，目标机解压到任意库目录（`$SYSLIB`，如 `/mnt/data/postgresql/pg17-syslib`）；方案 A 处先写的 `/etc/ld.so.conf.d/pg17-syslib.conf`（只含 `$SYSLIB` 一行）会在第四节第 3 步被**完整三行**（`$PG_HOME/lib`、`/usr/local/lib`、`$SYSLIB`）覆盖——配置文件名与压缩包同为 `pg17-syslib`，全程只有这一个配置文件，写完执行 `ldconfig` 即可，全程离线。若有 CentOS 7 ISO 也可用方案 C 挂本地源。

**Q8：方案 A 把库放到独立目录（`$SYSLIB`），会不会影响系统已有程序？**
→ 不会。这些库只在目录内新增、不覆盖 `/usr/lib64` 的系统文件；ldconfig 只是额外增加一个搜索路径。只有当某个库的 soname 与系统完全相同且版本更新时才可能被优先加载，由于源/目标同为 CentOS 7、版本一致，实际无影响。

**Q9：方案 A 之后 `ldd` 仍提示个别 `xxx.so => not found`？**
→ 说明该库没被收集脚本覆盖（通常是工具类库）。按第三节方案 A 的补库方法，在源机 `ldconfig -p | grep 库名` 找到真实文件，拷到目标机库目录 `$SYSLIB/` 后再 `ldconfig`。

**Q10：`postgres --version` 报 `error while loading shared libraries: libicui18n.so.50: cannot open shared object file`（或其它某个 .so）？**
→ 说明系统运行时库还没被 `ldconfig` 找到（系统库包没解压、没写 ld.so.conf.d、或没跑 `ldconfig`）。先**一次性列出所有缺失库**，避免逐个试错：

```bash
export PG_HOME=/mnt/data/postgresql/postgresql-17.11   # 换成目标机实际 PG 目录
for f in "$PG_HOME/bin/postgres" "$PG_HOME/bin/psql" "$PG_HOME/lib/"*.so; do
  ldd "$f" 2>/dev/null | grep 'not found' | sed "s#^#$f: #"
done
```

然后按缺库处理（按第四节第 3 步，把三类路径一次性写入 `/etc/ld.so.conf.d/pg17-syslib.conf` 再 `ldconfig` 即可解决绝大多数）：
- 缺 `libpq.so.5`、`libecpg.so.6`、`libpgtypes.so.3` → 这些库**就在 `$PG_HOME/lib` 里**，是没把 PG lib 目录注册给 ldconfig；把 `$PG_HOME/lib` 加入 ld.so.conf.d 后 `ldconfig`。
- 缺 `libicui18n/libicuuc/libicudata`、`libssl/libcrypto`、`libxml2`、`libjson-c`、`libstdc++` 等 `/usr/lib64` 库 → 系统库包（方案 A）没就位，检查 `$SYSLIB` 是否解压、ld.so.conf.d 路径是否与实际一致，再 `ldconfig`；包里没有的按 Q9 从源机补拷。
- 缺 `libproj/libgeos_c/libsqlite3` → `/usr/local` 依赖没就位，确认 `pg17-deps.tar.gz` 用 `-C /` 解压（落到 `/usr/local`）、`/usr/local/lib` 已加入 ld.so.conf.d 并 `ldconfig`。
- 修完再跑上面的循环，**无任何输出**后 `postgres --version` 即正常。

**Q11：`psql: command not found`，或环境变量里是 `PGHOME` 导致找不到目录？**
→ PG 安装目录的环境变量名是 **`PG_HOME`**（带下划线），由 `install_postgresql.sh` 和 `migrate_pg17_deploy.sh` 统一写入 `/etc/profile`：

```bash
# PostgreSQL Environment
export PG_HOME=/mnt/data/postgresql/postgresql-17.11
export PGDATA=/mnt/data/postgresql/data
export PATH=$PG_HOME/bin:$PATH
export MANPATH=$PG_HOME/share/man:$MANPATH
# End PostgreSQL Environment
```

若 `/etc/profile` 里是旧的 `PGHOME` 写法或根本没有该块，重新执行部署脚本（第 8 步会幂等改写），或手工执行第六节第 4 小节的命令，然后 `source /etc/profile`（或重新登录）。注意 `PG_HOME` 指向的是 **bin 的上一级**（如 `.../postgresql-17.11`），不是 `/mnt/data/postgresql`。

> **PG 目录可以换位置**：整目录移到如 `/mnt/data/postgresql/postgresql-17.11` 不影响运行（PG 按二进制相对路径找 `../lib`、`../share`）。但 `/usr/local` 下的 geos/proj/sqlite 是按**绝对路径**链接的，必须固定在 `/usr/local`，不能随 PG 目录一起移动。
